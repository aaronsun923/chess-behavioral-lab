## 1. 命题与识别策略

### 1.1 v1 §7.2 的问题

v1 §7.2 把 `WPL_opponent_next` 回归到 `WPL_self` 上。这个回归分不开两条路径：

- 路径 A：人偏离引擎的走法把对手带进了更难的局面，对手因此犯错。
- 路径 B：人本来就处在难局面（所以 WPL_self 高），难局面延续到对手，对手因此犯错。

v1 的复杂度协变量控制的是**走棋方**的局面难度，不是**对手**在下一手面对的局面难度。所以 B 没有被排除。这就是共享难度混淆。

### 1.2 本 SPEC 的策略

v2 已经对每个偏离行评估了两个后继局面：实际分支 P(m_played) 和反事实分支 P(m_best)。也就是说，对手在两条分支上各自面对的决策问题，其难度特征我们都有。

识别分三步：

1. 用全部已评估的行拟合一个**期望误差模型**：给定一个局面的难度特征和行棋者的水平、时间，预测行棋者的 WPL。这是一个 nuisance model。
2. 用这个模型分别预测对手在 P(m_played) 和 P(m_best) 上的期望误差。两者之差是"偏离带来的、纯粹由局面难度解释的对手额外误差"，即路径 A 中引擎在原则上也能看见的那部分。
3. 对手在实际分支上的**实际误差**减去模型预测的期望误差，是"超出难度解释的对手额外误差"。这一部分才是引擎目标函数里没有的信息（对手的可错性），才是互补的直接证据。

**识别假设（必须在报告里原文写出）**：给定局面特征、对手 Elo、对手时钟，对手的误差与"这个局面是由人偏离还是引擎首选走出来的"无关。这个假设排除了可测的难度混淆，没有排除不可测的因素（对手准备、心理状态）。本设计不是随机试验，报告不得使用因果语言强于"在识别假设下"。

## 3. 需要补算的量

### 3.1 对手实际回应的误差

对每个偏离行 i：

- P_i = P(m_played)，v2 已有其 MultiPV-5，存的是原走棋方视角的 `WP_self`。
- r_i = 对手在 P_i 上实际走的回应，从 PGN 读。
- 若 r_i 在 P_i 的 MultiPV-5 线内，直接取其 WP；否则对 P_i 执行 r_i 后的局面跑一次评估（**[LOCKED]** depth 15，MultiPV 5，Threads=1，Hash=128，独立评估，与 v1 一致）。
- **[LOCKED]** 对手视角的 WP = 100 − WP_self。所以

  ```
  WPL_opp_actual_i = WP_self(r_i) − WP_self(P_i 的对手第 1 选择)
  ```

  该值非负（对手第 1 选择使 WP_self 最小）。**写显式测试**：对随机 200 行断言 `WPL_opp_actual >= 0`，同时用 v1 的镜像测试重跑一遍视角翻转。

- **[LOCKED]** 温莎化上限沿用 v1 全样本算出的那个 1% 阈值数值，不重新估计。保留 `WPL_opp_actual_raw`。
- 若 m_played 之后对手没有回应（认输、超时、和棋结束），该行丢弃并计数报告。若对手回应落在中局窗口之外，**保留**，回应发生就算数。

### 3.2 两条分支上对手面对的局面特征

对 P(m_played) 和 P(m_best) 各算一套，定义完全相同，全部从 **P 的行棋方（即对手）** 视角：

| 变量 | 定义 | 来源 |
|---|---|---|
| `wp_level` | WP_opp(P) = 100 − WP_self(P 的第 1 选择) | v2 |
| `gap_12` | WP_opp(第 1) − WP_opp(第 2) | v2 |
| `spread_15` | WP_opp(第 1) − WP_opp(第 5) | v2 |
| `n_legal` | 合法走法数 | python-chess，无需引擎 |
| `n_reasonable` | 5 WP 点内的 MultiPV 线数，右删失于 5 | v2 |
| `eval_volatility` | \|WP(P) − WP(P 之前两个 ply 的局面)\| | 序列，两分支共用同一个"两 ply 前"的局面 |
| `opp_elo` | 对手 Elo | v1 |
| `elo_diff_opp` | opp_elo − player_elo | v1 |
| `time_pressure_opp` | 对手在该 ply 的剩余时间 / 初始时间 | PGN %clk |

- **[LOCKED]** `wp_level` 必须进模型。误差率随局面优劣非线性变化，v1 没控这一项。
- **[LOCKED]** 反事实分支的 `time_pressure_opp` 取实际值（反事实只改走法，不改时钟）。
- **[LOCKED]** 无 %clk 的局，整局排除，不插补，报告比例。与 v1 一致。

### 3.3 尖锐度

`ΔRISK_steep` 沿用 v2 定义与数值，不重算。正值 = 人选了比引擎首选更尖锐的走法。

## 4. 期望误差模型（nuisance model）

### 4.1 训练集

- **[LOCKED]** 主训练集 = v1 中满足以下条件的行：该行的前一个 ply 已被评估，且前一个 ply 的走法是引擎首选（`m_played == m_best`）。理由：跟在偏离之后的行是"受处理"的行，若命题为真，它们的误差被抬高，混进训练集会把处理效应吸进基线，使检验偏向零。
- 报告主训练集行数与占全部行的比例。
- 前一个 ply 未被评估的行（v1 每局采样 30 手造成的断档）不进主训练集。报告断档比例。

### 4.2 模型

```
WPL ~ wp_level_z + wp_level_z^2 + gap_12_z + spread_15_z + n_legal_z
      + n_reasonable_z + eval_volatility_z + elo_z + time_pressure_z
      + (1 | player_id)
```

- 线性混合模型。所有连续预测变量标准化，标准化参数在训练集上算，预测时沿用。
- **[LOCKED]** 5 折交叉拟合，按 `game_id` 分折，`fold_seed = 20260905`。对偏离行 i 的预测必须来自没见过该局的那一折模型。
- 预测只用固定效应部分。两条分支的预测之差不含玩家截距（同一个对手），所以随机截距在差分里抵消。报告时说明这一点。
- 报告：系数表、每折的样本外 R²、预测值与实际值的分箱校准图（10 箱）。

## 5. 因变量构造

对每个偏离行 i，单位是 WP 百分点，全部从**偏离者**视角，正值 = 偏离划算：

```
E_played_i = Ê(WPL | X_played,i)                 # 对手在实际分支的期望误差
E_best_i   = Ê(WPL | X_best,i)                   # 对手在反事实分支的期望误差

CF_i   = E_played_i − E_best_i                   # 难度可解释的对手额外误差（引擎原则上可见）
RES_i  = WPL_opp_actual_i − E_played_i           # 超出难度的对手额外误差（引擎不可见）

NET_expected_i = CF_i − WPL_self_i               # 只靠难度，偏离是否划算
NET_realized_i = WPL_opp_actual_i − E_best_i − WPL_self_i
               = CF_i + RES_i − WPL_self_i       # 实际发生的净收益
```

`NET_realized` 是主因变量。`RES` 是互补机制的直接量。`CF` 用于分解。

## 6. 检验（全部事先写定）

**[LOCKED]** 分析行限定 `WPL_self ∈ (0, 5]`，与 v2 §4.1 同一区间，报告占比。

### 6.1 H1：平均而言，偏离是否划算

```
NET_realized ~ 1 + (1 | player_id) + (1 | game_id)
```

核心量：截距及 95% CI。同时报告等价性检验（TOST）。

- **[LOCKED]** 等价区间 ±0.5 WP 点，约为分析带内 `WPL_self` 中位数的四分之一，即净收益若小于典型偏离代价的四分之一，视为实际等价于零。设计时预估该中位数约 2 WP 点；实现者报告实测中位数，若实测值偏离 2 超过 50%，停下报告，不自行调整区间。

预期：基于 Vaccaro 等 2024 的元分析方向，截距很可能为负或不可区分于零。这不是失败，是 H2 到 H4 的背景。

不对称性说明（报告原文写出）：`NET_realized` 在实际分支用观测值、在反事实分支用模型期望值，噪声只来自一侧。识别假设下无偏，但方差被抬高，CI 会偏宽。这是设计的已知代价，不是缺陷。

### 6.2 H2：尖锐度是否预测净收益

```
NET_realized ~ ΔRISK_steep_z + WPL_self_z + gap_12_orig_z + eval_volatility_orig_z
               + time_pressure_opp_z + elo_diff_opp_z
               + (1 | player_id) + (1 | game_id)
```

`gap_12_orig`、`eval_volatility_orig` 是**原局面**（偏离者走棋时）的难度，来自 v1。

核心量：`ΔRISK_steep_z` 的系数。正值 = 更尖锐的偏离净收益更高，即 P4 报告的 pressure-seeking 是有效策略而不只是偏好。

### 6.3 H3：条件（仅两个交互，不再加）

在 H2 模型上加：

```
+ ΔRISK_steep_z : time_pressure_opp_z
+ ΔRISK_steep_z : elo_diff_opp_z
```

- 预期一：对手时间越紧（`time_pressure_opp` 越小），尖锐偏离的收益越大，交互系数为负。
- 预期二：对手相对越弱（`elo_diff_opp` 越负），尖锐偏离的收益越大，交互系数为负。
- **[LOCKED]** 用对手的时钟，不用偏离者的时钟。v1 用的是走棋方时钟，那是错的变量：诱发误差的是对手的时间压力。

### 6.4 H4：机制分解

把 H2 的因变量分别换成 `RES` 和 `CF`，同一右侧，各跑一次。

- `RES` 模型中 `ΔRISK_steep_z` 系数为正 = 尖锐走法诱发的对手误差**超出**难度所能解释，这是"人携带引擎没有的信息"的直接证据。
- `CF` 模型中系数为正但 `RES` 模型中为零 = 尖锐走法的收益完全来自把对手带进难局面，引擎原则上可以算出这一点，不构成互补。
- 报告两个系数的相对大小。这是全文最重要的一张表。
