3. 风险指标定义(本 SPEC 的核心,全部 [LOCKED])

对每个局面走法行,需要对两个走法分别计算风险:人类实走 m_played 与引擎首选 m_best。

3.1 评估流程

对走法 m:在当前局面执行 m,得到后继局面 P(m),对 P(m) 跑 Stockfish depth 15, MultiPV 5(与 v1 同配置,Threads=1, Hash=128,独立评估)。所有 cp 按 v1 的 WP 公式转胜率,视角为原行棋方(即走 m 的一方;注意 P(m) 中行棋方是对手,符号必须翻转——此处写显式测试,v1 的镜像测试直接搬来用)。

3.2 主定义:惩罚陡峭度(punishment steepness)
RISK_steep(m) = WP_self(P(m) 的对手第1选择) − WP_self(P(m) 的对手第5选择)

含义:走完 m 后,对手最好与第5好回应之间、我方胜率的落差。落差大 = 对手必须走准我才安全、走偏我就赚 —— 这是"高风险高波动"局面;落差小 = 无论对手怎么走结果都差不多 —— "低风险可挽回"局面。
(注:对手第1选择对我方 WP 最低、第5选择最高,故该值非负。)

3.3 敏感性定义(仅此一个,不再加)
RISK_var(m) = std( WP_self over P(m) 的 MultiPV 5 条线 )
3.4 因变量
ΔRISK = RISK(m_played) − RISK(m_best)        # 负值 = 人类选了更低风险的走法
ΔWPL  已有(人类走法的期望损失,v1 的 WPL 列)
4. 检验(全部事先写定)
4.1 主检验:同等期望损失下的风险偏好

限定 WPL ∈ (0, 5] 的行(人类确实偏离了引擎、但偏离不大——"有选择余地"的区间;[LOCKED],区间事先定死,报告时注明其占比):

ΔRISK_steep ~ WPL_z + gap_12_z + eval_volatility_z + time_pressure_z
              + (1 | player_id) + (1 | game_id)
核心量:截距。 截距显著为负 = 控制偏离幅度后,人类系统性选更平缓的路径 → 命题成立方向。
同时报告无模型的原始配对统计:ΔRISK_steep 的中位数与符号检验(多少比例的行为负)。
4.2 连接 Paper 1:风格预测风险偏好

玩家层:将 v1 试点中每人的平均 ΔRISK_steep 对 Paper 1 的 style 向量(至少 PC1)回归。事先假设:阵地极(PC1 负向)预测更负的 ΔRISK(阵地风格 = 低风险偏好的行为表达)。roster 成员限定(理由同 v1 的 §8.1 重跑)。
